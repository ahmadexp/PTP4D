# PTP4D 0.5 release validation

Release prepared on 2026-11-20 from the merged servo/CoreMIDI source. The only
DOS source change after the [six-servo hardware trials](servo-20261120/) is the
displayed banner, from `PTP4D 0.5-dev` to `PTP4D 0.5` in `src/PTP4D.C`.
The controller, timing, transport, and clock-mode code is unchanged.

The checked-in `bin/PTP4D.EXE` and release asset contain the same bytes. The
release binary was freshly built twice with Borland C++ 3.1, huge memory model,
through `build-dos.py`; both builds matched byte for byte. Source files retained
their DOS CRLF line endings. Compiler and private firmware files are not bundled.

Both builds ran DOSBox-X configured as a 486 with FPU emulation disabled:

- Product and test builds completed without compiler warnings.
- Help reported version 0.5 and all servo switches.
- Missing-driver probes returned without accessing nonexistent hardware.
- Unsupported DOS-derived GM mode was refused before the resident-driver probe.
- Servo, clock/calendar, options, and MIDI suites all reported PASS.

The release executable has not been installed or rerun on the physical PC110.
Physical timing results refer to the development artifact above, which remains
identified in the original logs. No new physical accuracy claim is made by
changing the version banner.

## Portable checks

`python3 tools/test.py` passed on macOS with:

- C89 builds, warnings as errors, AddressSanitizer, and UndefinedBehaviorSanitizer.
- Wire, MIDI, options, calendar, and servo regression suites.
- 37 simulated DOS sessions, including both stale-token regressions for every
  host servo and the existing failure/cleanup cases.
- 33 Python tests, including exact identity/endpoint selection, passive mode,
  grandmaster lifecycle, native CoreMIDI virtual I/O, recorded hardware
  timestamp evidence, and the published binary checksum.

The GitHub workflow runs the same portable suite on Linux and macOS. The native
CoreMIDI test is macOS-only. The proprietary DOS compiler is not required by CI.

As a release check, all six hardware reports were independently rerun through
`tools/analyze.py` against their corresponding grandmaster logs. Each again
matched all 128 retained t1/t4 pairs and offset/delay calculations, with zero
grandmaster timestamp errors and verified STOP.

## Published graphs

`tools/plot_servos.py` produced three PNG/SVG figures and a combined 768-row CSV
from the existing hardware analyses. It verifies monotonic master timestamps,
all retained t1/t4 match counts, offset/delay arithmetic, and final-window
statistics before plotting. The images were inspected for readable axes,
legends, units, and capture-window labels. No measurements were synthesized,
smoothed, or extrapolated into the missing startup interval.

The figures show reported PTP offsets, reported frequency corrections, and
final-window offset distributions. They do not measure external PPS alignment,
absolute UTC accuracy, or long-term stability. The underlying trials used
`/SYNC NONE`, with no DOS/RTC setters. PHC2DOS and DOS-controlled GM operation
remain outside the physical validation.
